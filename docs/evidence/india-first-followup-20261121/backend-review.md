## Reproduced defects and minimal corrections

1. **Historical guardian could revoke an independent reader’s new session.** Actual PostgreSQL fixture: direct child account → independent-capacity transition → fresh reader sign-in → former guardian withdraws the already-withdrawn historical grant using its current version. The endpoint returned200 and the new independent reader became signed out. Correction: already-withdrawn grants return their unchanged state after the normal version check; an account-permission withdrawal revokes child sessions only while the locked child is still guardian-managed. Version conflicts and operation receipts remain enforced. Regression repeats withdrawal with fresh operation IDs and confirms session epoch/version/timestamps are unchanged; a stale version still fails412. The related former-parent account-deletion path already filters `child__guardian_managed=True`; its new regression proves it leaves independent readers unaffected, without changing that path.

2. **Concurrent independence and renewal could deadlock at commit.** The event-coordinated PostgreSQL test first held the child inside independence, then let renewal hold the parent and wait on the child. Independence’s deferred foreign-key check required a parent `KEY SHARE` at commit, creating an actual cycle. The independence endpoint returned503; PostgreSQL logged `deadlock detected` with COMMIT versus sorted household `FOR UPDATE`. Correction: independence snapshots existing linked guardian IDs and locks those User rows plus the child in ascending primary-key order before child/grant mutation. It then rechecks current password, verification and managed state. Parent inactivity does not block the reader’s transition. This matches the public parent-created household model; no unrelated guardian can attach a child by guessing an email. No distributed lock, queue or retry conceals the defect. Tests coordinate both actual orderings, observe the waiting PostgreSQL backend, and require either renewal denial after independence or withdrawal of the newly committed renewed grant by independence.

3. **Native Google recovery lost the reader/lesson destination.** The saved OAuth return path only selected locale; the303 recovery omitted it. Correction: carry the validated local destination as URL-encoded `return_to`, retaining the public error allowlist and no-referrer/no-store headers. If a native error occurs at the exact start endpoint before saved state exists, only that endpoint may use its validated `return_path` query. Callback queries are never a fallback. Tests cover Reader/lesson paths with query values, unsafe external/protocol-relative/control-character paths, no OAuth state/code/nonce leak and the maintained signed-OIDC callback recovery.
