# Earnalism Maison Low Level Design

This specification is the build brief for Ronik's engineering team. We will implement the approved Maison experience as one Django application on Render, PostgreSQL on Neon Scale Singapore, public assets on Cloudflare CDN backed by R2, private book and audio objects on R2, and authorized video on Stream. This document defines module behavior and operational rules. The accompanying OpenAPI, SQL, cache policy, payload examples and screen matrix define the detailed contracts that code must implement.

These are proposed implementation contracts, not a description of deployed software. No production database, merchant configuration or migration has been changed. Capacity, recovery and browser support remain acceptance work. The earlier architecture and elastic-cost calculations remain applicable; this specification adds detail rather than replacing their availability qualifications.

## 1 Contract ownership and scope

The package is version 1.1.0, dated 17 November 2026. OpenAPI is the authority for HTTP paths, fields, status codes and operation names. database.sql is the proposed relational constraint and index contract; Django migrations become the deployed authority after their equivalence is verified. cache-policy.json governs cache eligibility and TTL. The screen matrix maps S01 through S26 to routes and operations. This document governs transactions, state transitions and operational behavior. Conflicts between these files must be resolved before the affected implementation merges; do not create a second interpretation in code.

P0 includes catalog and bilingual discovery, accounts, Reader, audio, eligible video, text/audio switching with measured maps, annotations, progress, curated learning and quizzes, SDE learning paths, offers and hosted checkout, entitlements, personal lists, device controls, eligible offline text/audio, staff publishing and recovery operations. Video capability can remain unavailable until an approved video exists. A reader-only pilot is a reduced pilot, not full P0 completion.

S14 Clips, S19 timed or recorded readiness, S25 gifting, family profiles, children's profiles, public social features, voice search, dictionary, word-level read-along, consolidated annotation hub, video offline and native apps remain later scope. Their review screens describe direction, not working backend endpoints. P0 Reader annotations remain supported independently of the later hub. No dead controls appear in the production shell.

Some P0 designs have commercial or provider rollout gates. Recurring Pass contracts are designed now but disabled until merchant mandates, prices, notices, tax treatment and cancellation behavior are approved and tested. Fixed-duration nonrenewing offers use the same access model. Email link and Google sign-in require verified configuration; existing password users retain a recovery route. Phone OTP remains disabled until its provider, delivery registration, cost limit and account-link tests are ready. These gates do not authorize purchases or account creation.

## 2 Runtime and repository structure

Target Python 3.13, Django 5.2 LTS with the supported security patch, PostgreSQL 18 with the provider-supported current minor, psycopg 3, Gunicorn WSGI and React with TypeScript for the interactive islands. Node 24 LTS is a build tool only. Pin exact resolved versions and image digests in the new repository's lock files when the implementation starts; the version families here do not justify an old vulnerable patch. Django's published compatibility and PostgreSQL's support policy support these choices. [Django compatibility](https://docs.djangoproject.com/en/5.2/faq/install/), [PostgreSQL support](https://www.postgresql.org/support/versioning/), [Node releases](https://nodejs.org/en/about/previous-releases).

Use accounts, catalog, reader, learning, billing and operations Python modules in one project. Each module contains models, validation schemas, views, a small services.py for multi-record business operations, admin configuration and focused tests. Query helpers belong beside the consuming module. Avoid a generic repository layer, dependency injection container, event bus and service-per-entity structure.

Templates provide navigation, discovery, title, track, account and legal pages. client/ contains Reader, Player and Quiz islands, shared tokens and their small API client. static/ contains fingerprinted build assets. An island receives a small JSON bootstrap using Django's safe JSON serialization, never interpolated executable script or full paid text in a public page. Templates and JSON views call the same authorization and business functions.

The image builds frontend assets once and runs collectstatic. One web process serves Django. The identical image supplies scheduled maintenance commands; there is no standing Node server, local media volume or worker cluster. Keep the new repository separate from the legacy application. Copy reviewed design assets and needed behavior, not historical guardrail machinery or production scripts.

## 3 Request lifecycle and bounded concurrency

Cloudflare terminates the public edge connection and forwards to the Render custom domain over verified TLS. Django accepts only configured hosts. A private origin header injected by the edge is checked in constant time on application routes; edge rules replace any caller-supplied copy. The minimal liveness endpoint is the only header exception. That exception does not expose configuration or database details. Use a staging-only configuration for local access; never weaken production host or TLS checks for preview.

Middleware order is request ID and structured timing, security and host validation, origin check, session, locale, CSRF and authentication. Request IDs are generated if absent or invalid; accept only a bounded opaque pattern, never reflect arbitrary header text. Controllers parse the declared JSON schema, reject oversized bodies and unsupported content types, authorize the object, call one operation, and serialize only its public fields. Staff responses have separate schemas so rights documents and internal source URLs cannot leak through a public serializer.

Begin with two Gunicorn gthread workers and two threads per worker. There are at most four request database clients per instance, 24 across six normal replicas, and 48 during a full rolling overlap. Keep two additional direct maintenance connections plus operator headroom; backend active-query capacity must be qualified at Neon's minimum CU. No request creates an extra unbounded pool. Use transaction pooling, disable server-side cursors on the pooled connection, and use a direct connection for migrations and exports. Do not hold session advisory locks through the transaction pool.

Proposed bounds are 30 seconds Gunicorn worker-heartbeat timeout (not a hard gthread per-request deadline), 30 seconds graceful shutdown, 3 seconds database connect timeout, 2 seconds lock timeout and 5 seconds normal statement timeout. Set longer limits locally in the export or explicit maintenance transaction, not globally. Provider HTTP calls use a 3-second connect timeout and 8-second total budget, with no blind retry of an uncertain financial mutation. Main JSON request bodies are at most 256 KiB; webhook bodies are at most 1 MiB; media bytes upload directly to storage. These values are initial acceptance settings, not measured capacity. [Gunicorn configuration](https://gunicorn.org/reference/settings/), [Django connection behavior](https://docs.djangoproject.com/en/5.2/ref/databases/).

Request logging records route template, method, status, duration, request ID, coarse error category and pseudonymous actor ID where justified. Redact cookies, authorization headers, CSRF and email-action tokens, signed URLs, search text, annotations and raw payment bodies. Error responses never contain SQL, stack traces, bucket credentials or provider secrets.

## 4 URLs and server rendering

Use locale-prefixed public routes, such as /en/ and /bn/, so a shared cache does not have to guess language from cookies. Canonical route families are welcome, sign-in, explore, search, titles/{slug}, read/{edition_id}, listen/{edition_id}, watch/{edition_id}, series/{slug}, learn, tracks/{slug}, lessons/{lesson_id}, interview, pass, checkout/{order_id}, vault, vault/downloads and settings. S09 and S11 are boundary states inside Reader and Player; S15 is a sheet, not an independent public product. Deferred S14, S19 and S25 routes return an honest unavailable page or stay unlinked.

Protected consumption routes return a small application shell after authorization. Public title pages never embed full protected Reader data or a private object key. A request for a retired slug returns 410 when its former public existence is safe to reveal, otherwise 404. Preserve stable canonical slugs; keep an explicit redirect record for a renamed public slug. Never redirect a private token through analytics or an external open redirect.

Query parameters encode catalog filters, sort and search. Permit only declared names and bounded values. Canonical discovery links omit session and payment state. return_to is a relative allowlisted product path; external URLs, scheme-relative paths and sign-in loops are rejected. Encode the content anchor separately from the destination route and verify it belongs to the edition when returning from checkout.

## 5 Identity and account linking

Use a custom Django user model from the first migration with a normalized unique email and a framework-internal bigint key. Public member IDs are the UUID of the associated member profile; internal identity keys never appear in API responses. Use Django database sessions and maintained account/OAuth integration. Cookie names, lifetimes, role rules and token bounds are listed in runtime-config.json and OpenAPI. Session cookies are host-only, Secure, HttpOnly and SameSite=Lax. CSRF tokens are required for unsafe cookie-authenticated operations, including login and action-token consumption. Cross-origin application API calls are not enabled. Google uses exact registered redirect URIs, state and nonce, and PKCE where supported by the maintained integration.

Registration and reset initiation return generic delivery responses so arbitrary email addresses cannot be enumerated. Store the canonical sign-in email and a separate display value. Normalize domain/case consistently; never apply provider-specific dot or plus stripping to merge identities. Hash passwords through Django's maintained password hashers; never implement a custom password digest. A successful password reset invalidates every prior session/device binding and prior email action token; a new login is required. Linking a new provider is a separate freshly reauthenticated action, with its own disclosed session policy.

Email action tokens are cryptographically random, stored only as a keyed hash with purpose, account binding, expiry and consumed time. A link GET renders a confirmation page without logging in or consuming the token; the POST consumes it once inside a transaction after CSRF checks. Do not log the query string. Reset and magic sign-in use separate purposes and short expiries. Resend invalidates older active tokens for that purpose; a duplicate consume produces a safe expired/used response rather than a second action.

Google provider subject, not mutable email alone, identifies a linked provider. A matching email prompts explicit verified linking; it does not silently join two accounts. Staff MFA is required before admin operations, using a maintained TOTP or WebAuthn integration. Recovery codes are hashed and single use. Support cannot see passwords, magic tokens, private annotations or raw payment credentials.

Each active session has a device record with a user-chosen label, coarse recent activity and revoked time. Avoid device fingerprinting or hardware identity claims. Revocation deletes the server session and rejects later API calls; it cannot guarantee deletion of content already copied to an offline browser. Client logout clears that account's local manifests, files and write queue, after offering to synchronize unsent personal edits where possible.

## 6 Authorization and paid access

One check_access function receives user, edition, format, action, country context and server time. Actions distinguish preview, stream, offline_download and staff_review. Evaluation order is account/session validity, edition publication, exact format release and asset revision, rights territory/time/action, then free or paid entitlement. A paid entitlement never overrides withdrawn rights. A released Reader edition does not make unapproved audio available.

Country context comes from the trusted edge's validated country header and declared account/merchant requirements. Replace caller-supplied forwarding headers. An IP-derived country is a delivery signal, not proof of residence or a complete compliance system. Unknown territory fails access for territorially restricted content; globally cleared previews can remain usable. Do not add a geolocation service or infer nationality.

Entitlements carry source, scope, starts_at and ends_at. Use a half-open interval: starts_at <= now < ends_at. Scope can cover a named edition, a track/bundle or the configured Pass catalog. The grant's revision binds the content and policy used. Check access on every content/media/license grant; grants are short-lived capabilities and their revocation latency is bounded by their own expiry. Do not authorize from a client flag, browser cache, stale membership response or Redis.

The server returns a reason code and allowed actions, not a raw internal rules trace. The UI distinguishes no released format, preview limit, missing entitlement, pending payment, expired download, withdrawn title and region unavailable. An already entitled user with a temporary grant failure sees Retry access, not Buy again.

Staff permissions are role-based: editor edits drafts/uploads, rights reviewer records clearance, publisher releases or withdraws an exact revision, support views bounded customer/payment status and opens a refund request, and admin manages configuration and role assignments. A single owner may hold multiple roles; the records still identify the performed action and evidence. Avoid turning routine onboarding into an unnecessary multi-service approval pipeline.

## 7 Catalog editions and publication

A Work is the language-independent intellectual grouping. Each Edition has language, immutable content revision, ordered units, metadata and format-specific assets. Pair EN and BN editions explicitly; pairing does not copy text, rights or release status. Assets are internal UUID records with checksum, byte size, MIME type, storage locator, format, language and readiness. A file's existence is not release authorization.

Draft imports accept normalized structured text and pre-produced media only. Reject invalid UTF-8, unsafe HTML, repeated anchor IDs, non-monotonic unit ordering, external script or event attributes, unexpected URLs and asset hashes that disagree. Sanitize Reader HTML using a small semantic allowlist. Preserve Bengali vowel signs, conjuncts, virama and joiners. Record the source/rights references privately; reader metadata contains only required attribution and approved product copy.

Staff upload authorization binds one generated object key, expected MIME type, expected byte limit and an expiry; the client cannot choose another bucket/key. Finalization checks object size/type and a trusted checksum verification result before marking ready. A client-supplied metadata hash or multipart ETag is not accepted as proof of SHA256 integrity. If the storage path does not supply a qualified checksum check, run a bounded streaming hash-validation command from the same image against the uploaded object before release. Keep lengthy validation separate from HTTP and the 45-second maintenance loop. A failed or incomplete upload stays private and unavailable; delete orphaned uploads only through a reviewed retention operation.

Publishing prepares immutable packages outside a long database transaction, verifies their hashes and presence, then locks the edition/release record and rechecks readiness, rights/time/territory, revision and actor permission. Commit publication state, searchable metadata and an outbox invalidation record together. A concurrent edit or expiry returns a version conflict; do not publish a different revision from the one reviewed. A scheduled release calls the identical operation when due and rechecks the current policy.

Withdrawal commits the unavailable state and revokes future grants first, then retries CDN purge through the outbox. Existing signed capabilities and permitted offline licenses expire on their stated bounds; public immutable preview copies may survive their documented cache interval or user copies. No mechanism promises recall of already downloaded bytes. A serious takedown runbook disables public objects and purges known URLs, records residual exposure and communicates the true scope.

Corrections create a new edition revision and a deliberate old-to-new anchor mapping. Do not silently move annotations to a similar sentence. Unmapped annotations retain their quote and original revision with an orphaned state. Original revisions remain private for required audit/recovery; public entry points resolve only to the current approved release.

## 8 Search and discovery queries

Store NFC-normalized search fields separately from display text. Use English full text for English metadata, simple dictionaries for Bengali, and pg_trgm for bounded typo fallback on short metadata. A reviewed alias table supports Banglish terms without claiming full transliteration or stemming. Search only live, territory-eligible metadata; do not index private notes into public discovery.

The query pipeline trims Unicode whitespace, bounds query length, normalizes NFC, tokenizes by locale, and applies exact/prefix matches before full text and controlled trigram fallback. Queries shorter than three meaningful characters use bounded prefix suggestions. Return stable cursor pagination with the sort tuple and ID, tied to the filter/query digest so a cursor cannot be reused with different filters. Reject malformed or expired cursors rather than performing an unbounded scan.

Use SQL joins and select_related/prefetch_related with explicit page bounds. The database companion lists each hot query and matching index. Initial budgets are at most eight SQL statements for public title/catalog requests, twelve for a private library page, and five for a content grant, excluding session setup. Measure these in representative tests; the numbers are budgets, not proof. Use EXPLAIN ANALYZE with production-like synthetic volumes before adding indexes. Avoid broad transcript/full-book fuzzy search until it has its own cost and rights qualification.

Home shelves are editorial first. Member Continue comes from that member's progress. A failed recommendation query falls back to editorial content without exposing another member's results. Personal home and Vault are private/no-store; only shared catalog fragments qualify for public caching.

## 9 Reader state and annotations

Reader renders one unit at a time and prefetches at most one authorized next unit. It stores edition revision, unit ID, anchor ID and offset, never a viewport page number as the canonical location. Pagination and scroll share the same position model. Changing font size or orientation reflows from the semantic anchor. Font and layout tokens remain the approved Maison files; browser zoom and semantic selection remain available.

Progress is saved after a chapter change, explicit pause, visibility transition and a 15-second active debounce. It does not post on every audio timeupdate or every scroll pixel. A write includes stable operation ID, last seen server revision, edition/content revision and format-specific location. The server validates anchor ownership and media duration, rejects impossible offsets, and increments the progress revision atomically. Client time is advisory, never the authority for overwriting a newer server value.

Duplicate operation IDs return the original result; the same ID with different content is a conflict. A stale base revision returns the current server position and a resolvable conflict. The user can keep the server position or explicitly apply the local one against the new revision. Do not silently take the largest page, latest client clock or furthest timestamp: intentional rereading is valid. Completion is explicit and separate from last position, so seeking to the end or opening a later unit does not complete preceding material.

Bookmarks and annotations belong to one user and edition revision. An annotation stores start/end anchor offsets, selected quote and checksum, one of four supported highlight colors and an optional plain-text note. Validate quote/offset consistency against the authorized revision. Never accept executable note HTML. Deleting an annotation is an idempotent user-scoped action, with short-lived deletion tombstones or operation receipts to prevent an offline replay from resurrecting it.

Use a bounded IndexedDB queue with stable IDs for offline personal writes. Coalesce only unsent progress for the same edition/format; never discard a note to make space. When the queue limit is reached, keep the draft locally, show a storage/sync problem and stop promising saved status. Reconnect requires current authentication and ownership; retry safe operations with exponential jitter. A queue cannot create an entitlement, payment, staff publication or provider refund.

## 10 Audio video and format switching

The Player island owns one audio element across mini and full views. Queue, speed, sleep timer and current chapter are application state; the media element is not remounted on every navigation. Sleep timers use a monotonic elapsed clock and are recalculated after suspension; they pause once at their target or chapter end. A changed system clock must not extend a timer indefinitely. Persist pause/progress before releasing the player. Media Session and PiP are feature-detected.

Private audio grants select an approved chapter rendition and return a short-lived URL plus asset ID, checksum, duration and expiry. Renew before the next chapter or after an expiry response, then retry the same semantic position once. Do not treat every provider 403 as expiry or loop endlessly. The initial progressive 48/96kbps proposal is explicitly selectable quality, not automatic HLS ABR; retaining automatic audio ABR requires its separate manifest/segment implementation and acceptance decision.

Stream tokens are issued only for the approved video and policy. Captions/transcripts carry language and measured timing status; an untimed transcript is readable but cannot advertise sentence seeking. Listen mode requires a released audio asset, not an improvised hidden-video downloader. Video downloads and video Trinity remain deferred.

Format switching loads an exact text/audio timing bundle with both content and media hashes. Validate nondecreasing times, interval bounds, anchor coverage and measured review status. Map the current anchor to a sentence start, not a guessed percentage of duration. When no valid map exists, offer an explicit chapter/start choice. Offline switching requires both packages and their matching map already downloaded. A stale checksum disables exact switching and explains the new revision.

## 11 Offline package behavior

An offline license is a user/device/revision/action record with server-issued expiry no later than the entitlement or rights expiry. The proposed default maximum is 24 hours, subject to the owner/offline rights decision in the decision register. Refresh requires online authorization. A license is application access policy, not DRM; a user who controls the browser can copy bytes or alter software. Clock rollback detection improves honest-client behavior but cannot guarantee tamper resistance.

Download steps are reserve local budget, request license and bounded manifest, stream to temporary account-scoped entries, verify every length/hash, atomically mark complete in IndexedDB, then expose Offline ready. Interrupted downloads remain resumable or removable, never ready. The full protected book is not placed in a public service-worker precache. Requests to account, checkout, grants and payment endpoints are network-only.

On reopen, check active local account, manifest/schema version, revision/hash integrity, expiry and known revocation/rights tombstone. Invalid licenses block playback/reading but preserve personal notes for recovery. On reconnect revalidate before renewal, sync personal edits and remove invalid packages. Remote logout/revocation affects the next connection immediately; an offline device may retain access until its previously issued license expires. Show that limitation in account/device help.

Storage estimate/persist are feature-detected. Audio offline needs Range support from the local file handler: honor a valid single byte range with 206 and correct headers, return 416 for unsatisfiable ranges, and avoid loading a whole large file into memory per seek. The offline spike must prove airplane-mode relaunch and range playback on the actual supported iOS/Android browsers. Do not silently declare video offline support or persist unlimited files.

## 12 Learning and quizzes

Tracks contain ordered lessons with prerequisites and explicit completion rules. SDE is the first Interview track. An access lock is distinct from an unmet learning prerequisite. Public lesson metadata can show the outline; protected content and quiz questions require the appropriate entitlement. Public question responses omit answer keys and correctness hints.

Attempt submission carries attempt ID, quiz revision, question IDs and selected option IDs. The server checks membership, duplicates, option ownership and quiz revision, scores against private answer data and persists the result atomically. One duplicate submission returns the same scored attempt. An offline quiz submission is pending until acknowledged online; it cannot award verified completion locally. A newer quiz revision requires an explicit restart or preserved scoring against the still-supported original revision, not mixing old choices with new answers.

Explanations become available after the allowed submission/review point. Repeating a quiz creates another attempt rather than overwriting history. Lesson completion updates the user's track state using the documented rule; simply loading a page does not confer mastery. No readiness percentage, certificate, employer affiliation or job outcome is inferred from P0 quiz scores.

## 13 Offers orders and payment reconciliation

Offers are immutable commercial versions: currency, integer minor-unit amount, tax treatment, product scope, duration, renewal type, availability and effective dates. The UI reads the server offer and shows the actual charge/renewal terms. Disabled or unpriced offers have no checkout button. Changing an amount or term creates a new version; an old checkout cannot silently accept the new price.

To create an order, validate the user and exact offer, lock the idempotency scope, persist an order snapshot and commit before calling the provider. Do not hold database locks across a network request. The provider request uses a unique local reference and the approved captured-payment flow. Store the provider ID in a second short transaction. If provider order creation times out after it may have succeeded, mark the outcome unknown and reconcile with provider records; never blindly create a second order because the browser clicked Retry.

Browser Checkout success is evidence to verify, not authority to unlock. Verify the signature against the server's stored provider order ID, fetch authoritative provider payment status where required, and compare merchant, order, amount and currency. Only an accepted captured/paid transition grants access. Authorized, pending and failed events do not grant paid access. The user can poll the local order, with increasing intervals and a visible pending state; do not charge again while the previous outcome is unknown.

For webhooks verify HMAC on the exact raw body before parsing the business payload. For a complete known verified event, one short transaction saves the unique receipt, locks the local order/payment, enforces unique provider payment and business grant source, applies the monotonic transition and writes entitlement/notification outbox state before acknowledgement. Unknown, ambiguous or incomplete events persist the receipt plus reconciliation outbox and acknowledge pending processing; a receipt alone is not payment or access success. Maintenance targets the next minute and alerts on captured payments without grants older than two minutes. No provider network call occurs inside either transaction. A duplicate event returns success only after its durable receipt exists. If the database is unavailable, return retryable failure instead of acknowledging lost work. Event order is not guaranteed. [Razorpay webhook guidance](https://razorpay.com/docs/webhooks/best-practices/).

Equivalent events with different IDs must still produce only one payment and grant. Late failure events cannot regress a captured payment. A refund uses a separate state machine and entitlement policy. Unexpected amount/currency/ownership enters review without access and raises an alert. Reconciliation processes unresolved local orders, provider events and post-restore gaps; it never initiates a fresh charge to repair a missing database row.

Refunds require a permitted staff action, reason, provider amount limit and stable local request ID. Lock refundable allocation, reserve the amount, call the provider outside the transaction and reconcile an uncertain response before retry. Sum completed/pending refund reservations cannot exceed the captured amount. A full refund or chargeback changes entitlement according to the disclosed policy; do not delete the original financial history. Tax invoices are immutable snapshots/revisions with explicit finance-approved numbering/tax rules, not a decorated transaction list.

## 14 Recurring access and legacy obligations

Recurring contracts model mandate authorization, active paid period, pending/past-due, cancel-at-period-end and ended states. A mandate alone grants no access; accepted captured renewal payment grants one unique paid period. Replayed renewal events cannot extend access twice. Terms and next charge appear only when confirmed by the provider. Dunning and pre-debit notices follow the configured provider/commercial policy, not a homemade daily charge loop.

Cancellation is a user request followed by explicit confirmation. Record the requested effective end and provider operation, show pending when the provider result is uncertain, and reconcile before confirming completion. For cancel-at-period-end retain already paid access until the paid period ends; no cancellation fee or immediate forfeiture is invented. Nonrenewing Sprint and preserved wallets have no misleading cancel-renewal button. Trials, pause and grace are disabled unless a concrete offer defines them.

Legacy wallet balances are a liability ledger and cutover decision, not an invitation to rebuild old charging machinery. Each obligation is imported exactly, settled/refunded or explicitly replaced with customer agreement. No automatic expiry or subscription conversion. If an unresolved wallet must remain consumable in the new platform, its metering/lease contract is a separate mandatory pre-cutover design item; that affected cohort cannot be cut over until it is specified and tested. Preserve the old path while resolving that item instead of inventing minutes-to-Pass arithmetic.

## 15 Background jobs and external side effects

Use two scheduled entries from the same image: maintenance every minute and encrypted export daily. The maintenance command has a bounded total runtime and processes due outbox jobs in small batches. Claim rows with SELECT FOR UPDATE SKIP LOCKED, set a lease owner/expiry, commit, call the external service, then record completion. A worker crash lets the lease expire. Do not keep a row lock open while sending email or purging CDN.

Job payloads contain internal references, template/version and idempotency key, not copied credentials or full personal notes. Email delivery uses the provider's idempotency feature if available; otherwise the outbox guarantees local deduplication but cannot promise exactly-once email after a timeout. A duplicate receipt email is preferable to a duplicate payment. Security-sensitive action tokens are purpose-bound and generated/stored through the accounts operation; a retried email cannot extend their validity silently.

Proposed retry delays are 30 seconds, 2 minutes, 10 minutes, 30 minutes, 2 hours and 6 hours with jitter, bounded by job relevance. After exhaustion mark failed, alert and retain a manual retry action. Throttled providers honor Retry-After. Scheduled publishing reuses the publication transition. Reconciliation and expired license/session cleanup are bounded portions of maintenance; long export or media generation never runs there. [Render scheduled jobs](https://render.com/docs/cronjobs).

## 16 Configuration and provider boundaries

runtime-config.json lists public settings, secret names, timeouts, limits, feature flags, job schedules, alarms and initial capacity. It contains no real domains, project IDs, keys or credentials. Per-environment configuration is validated at startup. Production must fail startup for missing critical secrets, unsafe DEBUG/host/TLS values or enabled billing methods without required provider fields. Optional unavailable video/OTP features stay disabled without preventing a reader-only staging environment from starting.

Razorpay, email, R2 and Stream each use one small provider adapter with a timeout, redacted error mapping and a contract test. No adapter owns business entitlements. Keep provider IDs behind internal IDs. Export source media and PostgreSQL using documented formats so moving away from a provider does not require rewriting business records. Secrets are managed in deployment settings and rotated with a scoped overlap; never place them in frontend bundles or the public review package.

One Render application autoscaler starts at 2 instances, caps at 6 and targets approximately 65% CPU with measured memory headroom. Neon starts with a proposed 0.5–2CU native range and autosuspend off. No autoscaler calls a manual database resize API. Mean CU, time at maximum, pool wait, hot working set and billed transfer determine resizing decisions. A six-instance app cap protects the database; higher app replicas do not repair a saturated writer.

Neon's multi-AZ storage and automatic recovery differ from a warm standby. Published AZ recovery is 1–10 minutes; the five-minute target is not preserved for every fault. Scale's compute-endpoint SLA is a service-credit contract, not an application recovery guarantee. The earlier cost model remains: about $112/month database and $336/month reader/audio platform at an unmeasured 0.5CU average, rising with load. A rightsized Render warm-standby profile remains a sizing-dependent fixed fallback. [Neon HA](https://neon.com/docs/introduction/high-availability), [Neon compute](https://neon.com/docs/manage/computes).

## 17 Observability and incident behavior

Use provider metrics and structured application logs plus an error tracker if approved. Render's native health check uses the minimal public liveness endpoint without DB access. A separate operator/synthetic readiness endpoint uses a dedicated probe secret and checks a short SELECT 1; do not assume Render native health probes can send that custom header. Neither endpoint exposes SQL or performs an expensive dependency sweep. Dependency failures return controlled503 responses on affected private routes while healthy public cached surfaces remain subject to cache policy. An external synthetic reads one public preview and verifies its bounded content hash. A protected synthetic uses a dedicated test account and never purchases real access.

Track request rate, 5xx, p50/p95/p99 duration, grant latency, database query time/pool wait, average/max CU, payment-pending age, reconciliation mismatches, outbox age/failures, export freshness and media errors. Proposed alert thresholds are defined in runtime-config.json. Compare SLOs by route and region rather than claiming global fast performance from one Singapore test. Financial alerts require immediate investigation; purely cosmetic analytics do not page the operator.

If DB connectivity fails, return temporary unavailable for private access and mutations; never infer payment failure or bypass entitlement checks. Public cached pages can remain usable only within their permitted cache policy. If R2/Stream fails, preserve the position and show retry/alternate released format. Do not proxy large files through Django as an emergency workaround. If mail fails, account state remains durable and the interface offers a truthful delayed/resend state.

For a bad release, roll back to the previous healthy image while retaining the compatible schema. For DB/region recovery, stop mutating traffic, restore into an isolated target, verify checksums/counts/sample content, reconnect using rotated secrets, reconcile provider financial events since the restore point, then reopen writes. Do not replay payment creation or publication blindly. Recovery targets remain ten-minute zonal design allowance and four-hour regional restore with up-to-24-hour export RPO until exercised.

## 18 Backups retention and privacy

Keep Neon restore history configured for seven days and a daily encrypted PostgreSQL export in a separate private R2 archive bucket with separate credentials. App delivery credentials cannot delete backups. Record manifest checksum, database/schema version, completion time and object size. Export includes relational business data; media objects have a separate inventory/hash manifest and cleared original source packet. A database dump alone does not recreate Stream assets or configuration.

Proposed backup retention is 30 daily exports and 12 monthly cutover/period snapshots, subject to measured storage cost and the privacy/tax retention decision. The previous cost model's history and transfer allowances are estimates; retained monthly growth requires recalculation rather than treating backups as free. Exercise a restore before launch and quarterly, and after a major schema or recovery change. A successful upload is not a restore test.

Retention uses record class and legal/business purpose. Expired action tokens and session rows are cleaned promptly; deduplication receipts survive the allowed offline/replay window; failed jobs retain enough bounded diagnostics for repair. Account deletion removes or pseudonymizes personal content and revokes sessions/licenses, while legally required invoices/payments remain restricted with a reason and end date. No unsupported seven-year legal claim is hard-coded. Finance/privacy must supply the jurisdiction-specific retention schedule before public release.

Privacy export is asynchronous, authenticated and reauthenticated for delivery. Include user-owned profile, preferences, annotations, progress, lists and relevant account records in portable JSON/Markdown, with a short-lived private download. Never export another member's data, internal rights evidence, staff credentials or raw provider secrets. Deletion has an explicit confirmation and a visible status; it cannot silently cancel a pending refund or erase a liability.

## 20 Migration and rollback details

Use a migration runner with the direct database endpoint once per release, not independently on every web replica. Schema changes follow expand, deploy compatible code, backfill in bounded batches, then contract in a later reviewed release. Use CREATE INDEX CONCURRENTLY for large live indexes outside atomic migrations; handle failed invalid indexes explicitly. Separate statement/lock budgets prevent a migration from waiting indefinitely behind traffic.

New books are imported individually through the new staff draft flow after clearance. A dry run produces metadata/asset/hash/rights validation without publication. The legacy platform remains authoritative for existing balances and active consumption until a deliberate cutover. Do not classify old files/services as unused by filename or delete them as part of this specification.

Cutover freezes legacy purchases and mutable state for a defined window, snapshots balances/entitlements/progress/provider references, verifies liability resolution, switches callbacks/domain and ends old active leases. Keep the old system read-only for the agreed rollback window. A rollback after new financial activity requires reconciliation of those new obligations; changing DNS alone is insufficient. Only after the window and restore evidence may the owner authorize the exact old services/subscriptions for retirement.
