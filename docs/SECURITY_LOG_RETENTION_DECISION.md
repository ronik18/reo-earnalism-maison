## Exact gap

It does not prove180consecutive days of complete relevant ICT logs, retrieval ability, formal CERT-In point-of-contact record, or clock-source evidence. Resolve that location/production interpretation for the actual arrangement; do not assert either automatic India-only architecture or blanket overseas-storage sufficiency. ## Candidate record boundary

For inventory and any later approved implementation, limit security logs to UTC event time, opaque request/event correlation ID, system/component, action/result/status, authenticated actor/device identifier where necessary, source network identity only where required for investigation, and relevant administrative/configuration/security changes. Record successful and unsuccessful security events proportionately. Exclude request/response bodies, passwords/hashes, MFA/recovery secrets, session cookies, authorization headers, action tokens, OAuth codes, signed URLs, note text/manuscripts, export contents and support-message bodies. Any exceptional incident evidence is separately scoped, restricted and reviewed.

Inventory actual app/access/authentication/security/admin, database access/error/admin, CDN/WAF/security, storage access/admin, scheduled-job/backup execution and email transport/admin logs. Not every provider exposes every category on the current plan. Name unavailable categories rather than inventing export endpoints or claiming complete coverage. Operator-managed business-mail content is not an ICT-log archive; no mailbox inventory/deletion is authorized.

An approved collection would require scoped read/export credentials, encryption in transit/at rest, owner-controlled restricted access, integrity/checksum records, category/source/time-range manifests, redacted operational receipts, bounded retrieval tests, category-specific expiry and incident holds. Restrict access to the responsible operator and authorized root, with access evidence. Retention180days applies only to the qualifying log categories and any justified incident hold, not a blanket180-day extension for accounts, notes, support payloads or all audit records. Existing90-day routine cleanup would require an exact category reconciliation if the same events are legally required longer; this proposal does not silently amend it.
